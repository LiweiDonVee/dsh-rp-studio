# RP agent、最后一步与图形化 loop：实现边界与设计

日期：2026-10-24（Asia/Shanghai）。已实现独立 `dsh-rp-last-step` 0.1 与 RP Studio 1.2 联动；通用图由独立 `dsh-loop-studio` 提供。用户确认第一版只做预设迁移、热组装和呈现，接收现有 agent／工具的事实，不包含模拟、状态或结算引擎。

## 0.1 交付边界

- 原生预设编辑器支持 ST 导入、自建模块、阶段分类、必用与 Agent 只读策略、版本保存、固定故事版本、只读原件和编译预览。原始文本与预设版本不可变；Agent 只修改本会话覆盖层。
- 迁移通过配套 skill 和受约束补丁产生待审阅草稿；模型可见 ST 顺序、深度与扩展描述，未支持行为形成诊断，原始脚本不执行。迁移语义仍需用户审阅。
- 就绪绑定的原生 agent 获得作用域工具和 Agent/shared 模块。`rp_present` 必须是处理完成后的唯一直接工具调用；成功后结束回合。纯 PTC 会话可迁移、编辑、预览，不能启用终止呈现。
- 组装模型按需读模块、调整覆盖并观察程序诊断；编译和版本校验通过后冻结输入。正文调用只有公开方向包、render/shared 模块和显式公开材料，没有世界工具或主 Agent 历史。
- Loop Studio 可为迁移、组装、正文分别选择实际模型。缺省沿用会话选择；迁移尊重用户刚选定的下一模型，呈现沿用本轮实际主模型。调用不写全局默认。
- RP Studio 接收安全正文流及已确认的规范工具结果；回放尊重回退和工具调用关联。插件单独安装时可在生成记录页读取已提交稿件，该记录页是稿件档案，不代替故事分支。

尚未实现可选复核节点、自由编辑执行拓扑、正文专用重试按钮或任意旧 RP 末端命令拦截。取消、失败、锁冲突及版本冲突有回归测试；真实宿主验收使用模拟模型，不能证明任意真实模型的迁移或写作质量。实际交付与操作以 [插件说明](../../../packages/rp-last-step/README.md) 和 [验收记录](../../rp-last-step-acceptance.md) 为准。

以下保留初始架构探索，其中复核、显式返回 Agent 和单独重新呈现属于后续设计。

## 独立产品边界

通用图形化 loop 已拆为独立的 `dsh-loop-studio` 插件，其设计见 [通用 Loop Studio](2026-10-24-agent-loop-studio-design.md)。RP“最后一步”是另一个独立 runtime/agent preset 部分；不要求安装通用图插件，通用图插件也不依赖 RP。两者通过通用阶段参与接口联动。

RP Studio 保留阅读、角色状态和预设管理体验。RP runtime 声明“迁移（导入时）”“热组装”“最终正文”和可选“复核”阶段，使通用图插件能展示并配置这些真实节点。未安装图插件时使用 RP 自身的节点默认模型配置。原件、权限、模拟事实和呈现记录均由 RP 部分负责。

核心流程为：玩家行动 → agent 模拟与工具循环 → 冻结本轮事实 → 预设热组装与校验循环 → 最终正文 → 可选复核 → 提交呈现。模型路由使用调用节点的配置，不修改宿主全局选择。

## 一次迁移与每轮热组装

导入流程独立于每轮 loop：保留 ST 原件 → 结构解析 → 用户选定模型运行适配 skill → 查看条目拆分与差异 → 保存派生版本。授权明确时可以保存；锁冲突和缺失的必需能力阻止启用。重新导入来源的新版本建立新版本关系，不覆盖旧会话的来源。

配套 skill 位于 `skills/adapting-sillytavern-rp-presets/`。它区分剧情职责和呈现职责，保护原件、默认启停与用户锁，保留文风、角色语气和排版，记录未支持的 ST 行为。仅做字段转换不足以完成迁移。

日常热组装基于已适配模块运行。模型读取目录、按需读取正文、查看当前组合、提交修改并观察编译诊断。提交呈现时使用覆盖层的最新版本编译并冻结，不复用 agent 开始时的过期编译结果。

## 数据与权限

保留三个层次：不可变来源和版本；用户掌握的必用/只读与管理策略；agent 的会话覆盖层和本轮临时调整。必用与可编辑是独立属性。用户锁由实际接口和编译器校验，skill 负责识别需要迁移的语义；不能用新模块 ID 或覆盖顺序逃过锁。

每次呈现记录所用来源版本、用户策略版本、会话覆盖版本、冻结的实际提示词与事实输入、模型配置以及输出状态。分支、回退与重新呈现以这些记录为依据。预设的默认选用状态不会因导入而全部变成启用。agent 的会话修改不会保存回源文件或全局预设。

## 模拟结果与正文

模拟及工具结果拥有事实和状态；最终正文获得玩家可见事实、必要历史和明确的可创作范围。写作可以发挥感官、句式、节奏、口吻及获准的非结算细节。新物品、判定翻转、关系变化和玩家未授权的选择需要 agent 阶段处理。

完成模拟后通过明确的呈现准备/提交动作进入后续阶段，不能靠猜测某一次 LLM 输出是不是“最终回答”。dsh 的工具回合终结能力可用于呈现完成后的收尾。需要继续调查或改变剧情时，显式返回 agent 阶段并更新事实版本。

关闭复核时，正文流式进入 Studio，完整提交后成为可回放叙事。开启先审后显的复核时，暂存正文，复核完成再显示；界面明确展示该等待过程。复核反馈可以触发受限的正文重写，沿用同一事实和锁定约定。自动语义检查无法证明所有文字都完全符合事实，状态写入权限仍由程序限定。

正文失败或取消后保留已经完成的剧情阶段，不重新运行工具；重新呈现只重跑相应呈现子流程。换模型生成的新稿保留与前稿的关系，避免当作第二次剧情结算。

## 与现有代码的关系

- RP Studio 当前通过原生侧栏工作，可继续承载流程与预设 UI；沉浸阅读需要区分 agent 过程与最终叙事，现有全部 assistant 文本映射为 GM 的规则需调整。
- `dsh-prompt-presets` 的来源、版本、ST 解析和编译可以复用；需要补齐用户锁、agent 补丁、阶段职责及提交时编译，并适配其较旧的宿主接口。
- dsh 0.2.1-rc.2 提供作用域内 prompt assembly、agent 请求路由、LLM runtime、skill registry 和工具回合终结能力。现有 workflow 是模型编写脚本的编排能力，其阶段模型元数据不等于执行路由；本产品的图形配置必须绑定真实运行配置。
- 不重写 loop 已经冻结的模型请求；使用公开的配置接口与独立呈现调用，并记录每次呈现的实际输入。

## 可验收的结果

用合成 ST 预设证明：原件不变，默认关闭仍关闭，锁冲突不会被绕过，混合模块真正拆分，失败判定不会在呈现中变成成功。通过迁移稿人工/独立演练与结构校验区分验证层次。

用不同标识的假模型适配器运行图：证明每个节点确实调用所选模型，工具与程序节点没有多余 LLM 调用，复核关闭时不调用复核模型，本地节点失败时不暗中外传，取消和重新呈现不重复状态工具。真实宿主检查节点状态与实际请求对应、会话隔离、分支/回退、流式输出和配置版本；付费模型调用只在用户授权的实际验收范围内进行。

通用图插件与 RP 最后一步各自构建、安装和验收。上方 0.1 交付边界优先于初始探索中的未来能力。
