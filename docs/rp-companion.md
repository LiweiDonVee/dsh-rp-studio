# RP 助手与聚合入口

RP Studio 1.5.0 面向 DSH 0.2.1-rc.5。把 Studio、Loop、Story Kit、Database、Context、GM 和 RP 最后一步七包更新到同一 profile，重启 DSH。会话顶部与空白会话的 `RP ▾` 菜单打开故事三页、各插件自己的完整管理页，以及独立的 RP 助手。未启用的插件显示原因；没有 Studio 时，各插件仍有原独立入口。

`RP ▾ → RP 助手` 准备一个使用 `rp-companion` 的管理草稿，也可以在新会话的 Agent Preset 中直接选择“RP 助手”。入口填入引导并保留已有草稿，检查需求和目标故事 ID 后发送；不会自动发送模型请求。管理会话与正在演绎的 `rp-gm` 故事会话分开。

可以直接提出：

- “把这个原始角色 PNG 和世界书导入，列出可选开场。”
- “将这个 ST 预设改造成剧情处理与正文分离的草稿，说明还不能兼容的项。”
- “把已审阅预设应用到故事 [ID]，并把 writer 切到我指定的已有模型。”

请提供原始角色 JSON/PNG 文件路径。显示图片可能经过宿主规范化，原卡的 chara/ccv3 metadata 应以原文件为准。支持 Character Card V2/V3 JSON、静态角色 PNG、世界书 JSON、ST 写作预设 JSON、Story Kit 内容包 JSON，以及 TXT/Markdown/PDF 资料。JSON/文本上限为 8,000,000 bytes，PNG/PDF 为 24,000,000 bytes；这是助手文件工具的边界，超过后明确失败，不截断原件。ZIP 和来源脚本不执行。

角色卡和世界书是内容资产；RP 最后一步的写作 profile 是剧情处理、共享约束与最终正文的模块；DSH Agent Preset 是插件组成。这三者独立。助手能够用各 owner 的实际公共接口导入、编辑、迁移和配置，也保留 DSH 创造模式的正式组成开发工具与官方四个 authoring skills。新 `managing-rp-studio` skill 随 Studio 安装；LastStep 与 Story Kit 的适配 skill 随各自插件提供。

导入保留所属插件的原始来源、hash、顺序、默认启停与诊断。ST 迁移使用所选模型，产生新的待审阅草稿与报告；助手会查看 agent/render 两份编译预览。“导入/改造”只交付草稿；已经明确要求“改造并应用”的任务，可以在必要修正和检查通过后保存就绪版本，并绑定明确的故事 ID。未知宏、STJS、正则、深度插入与扩展保持来源数据，不承诺完整 ST 运行时等价。结构通过与实际文风质量分别评估。

管理写入使用宿主真实 sandbox policy 与原生批准机制。非完全访问模式可能要求批准本次具体操作；完全访问模式不重复确认。拒绝后不执行对应写入。文件读取沿用宿主正式文件服务；读取并非自动限定在 workspace。助手不改 owner 私有数据文件、宿主权限、事实审批或原生日志。

保存已有对象时使用当前 revision 与 base version。模块的 locked/required 与资料的 readOnly/mode/provenance 保持；锁定及禁用资料完整保留，必用项不删除。关闭模块不会静默启用；明确要求启用可编辑模块时，迁移报告列出该项及原因。同源派生预设不能借替换绑定绕锁；正常更换独立文风预设或从资料组合移出只读库仍然允许。资料组合变更保留故事 overlay。

开局先选定角色、玩家身份、开场、资料及预设的具体版本，再明确初始场景与事实。Story Kit 返回独立 GM 故事会话，助手读回开场、绑定和事实后给出目标 ID。失败恢复沿原启动编号继续，不多建故事。现有开局协议不承诺继承管理会话的目录。事实审批仍默认关闭，事实与正文的既有修改、审计和恢复流程保持。

每次操作都以 owner 实际回执和读回为准。缺插件、版本冲突、锁冲突、权限拒绝或不支持格式时，保留可读的错误与下一步。无幂等编号的导入若回执丢失，先核对库中实际新增内容，再决定重试。

开发验证使用 `pnpm plugin:test`、`pnpm plugin:build` 和 `pnpm plugin:package`。Companion 测试位于 `packages/plugin/tests/companion-*.test.mjs`，覆盖作用域、真实接口签名、权限前置、显式目标、保护检查、原字节/文件上限和状态路由；确定性单元测试不代表真实安装、模型文风或冷恢复验收，原生安装证据另记。
