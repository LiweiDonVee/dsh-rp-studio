# 适配判断与示例

## 有损语义与原样保存

SillyTavern 的 `prompts`、`prompt_order`、role、injection position/depth、marker、宏、扩展脚本和采样参数承担不同职责。保存导入原件与字段，并不表示目标 runtime 已复现其行为。

需要依据目标 runtime 逐项映射：条目顺序按实际选中的 `prompt_order`；消息深度插入需要有对应的历史装配能力；marker 需要目标宿主明确的内容来源。无法映射的行为列入迁移说明。未知字段保留供导出，不能无声丢失。

`temperature` 等采样设置是可供用户采纳的节点参数建议，能力和范围由所选模型确认；它们不覆盖用户的模型路由。原件中的 API 地址、脚本或指令也不构成执行或外传授权。

## 同一条目包含多种职责

来源条目：

> 每轮让 NPC 主动采取行动，遇到阻碍就增加新事件。使用克制的第三人称，细写动作，末尾输出状态变化。

派生为两个可追踪条目：

- **agent 条目**：在玩家行为与既有世界约定下决定 NPC 是否行动；新增事件通过模拟或实际状态能力处理，形成可见事实与状态结果。缺少对应能力时标注能力需求。
- **呈现条目**：使用克制的第三人称，细写本轮事实允许的动作；将已确认的结果自然呈现。可写内容的边界来自本轮呈现输入。

agent 条目不能再次塞进最终呈现提示词。状态变化由 runtime 决定记录方式；如果界面确实要求文字状态块，渲染该结构的已确认值，其文本不是第二个状态写入入口。

拆分后的条目保留父来源 ID；原启停和必用策略怎样继承，应显式写在对应关系中。没有目标系统的合法继承规则时，先交付草稿，避免猜测锁的含义。

## 变量与缺失信息

来源条目：

> 按 `{{getvar::npc_mood}}` 写对话，感人时 `{{setvar::trust::+3}}`。

适配后，agent 层负责信任变化的判断及其受支持的状态操作；呈现层读取本轮允许的 NPC 表现与信任结果。NPC 情绪未知时，由运行时约定选择省略、请求 agent 补充事实或只写可观察表现。不得擅填成“感动”，也不能因为文字写得感人而改写信任值。

## 失败结果演练

输入事实：玩家只说“我试着推门”；判定失败，门仍关闭；守卫留在门外；信任为 2。玩家未授权代写下一步动作与内心。

可用的呈现预览可以描写门板的阻力、停顿和已确认的声音；门不能在正文中被推开，守卫不能突然出现在屋内，信任不能因修辞而上涨。玩家下一步选择仍然开放。这个例子仅是边界检查，不是产品附带的角色或故事。

若用户锁定条目同时要求“每段少于 120 字”和“失败必须写成成功并发奖”，不能只提取前一句来声称整条锁仍被遵守，也不能在后面加高优先级指令架空后一句。报告完整条目的冲突，并说明用户可授权的具体修订。

## 输出的完成程度

迁移记录说明来源版本或由宿主计算的内容标识、目标约定、拆分和改写、初始启停、权限来源、未支持语义和行为检查结果。没有执行过的宿主编译、真实模型演练或状态写入，一律不当作已有证据。工具/API 的名字与 schema 来自实际能力目录，本指南不定义接口。
